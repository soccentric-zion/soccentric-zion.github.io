Why Zion exists

After 25 years in embedded software, the last 10 as a consultant, I kept rebuilding the same foundations on every project: image build, board bring-up, configuration, device management and testing. Weeks of work before the real product could even start.

Zion is those foundations for AMD Xilinx Zynq, built once and reused: the OS image, board layer, configuration, on-device services and a full validation stack. It shares its architecture with the other 9 platforms, and it is the starting point for my own client work.

Inside the platform

What each repository provides.

Production

Zion-OS

Yocto · kas

  • Yocto and OpenEmbedded image build for AMD Xilinx Zynq
  • Central kas configuration as the single build entry point
  • Containerized build through kas-container, or a local Makefile
  • Build script that covers every supported target
  • Secure-update key generation helpers
View repository ↗

meta-zion

Yocto layer

  • BSP and board layer for AMD Xilinx Zynq
  • BitBake recipes for the Zion platform software
  • Consumed by the kas configuration in Zion-OS
  • MIT licensed recipes with their license checksums
  • Changes go through pull requests to develop
View repository ↗

Zion-Configuration

Rust · web UI

  • webconfigd daemon plus a reusable webconfig-engine crate
  • Browser UI driven by board manifests and schemas
  • Appliers for network, Wi-Fi, WireGuard, firewall, GPIO, CAN, serial, time and SSH
  • Authenticated HTTP API with CSRF, TLS and live events
  • Persistent store with backup, audit trail and Yocto packaging
View repository ↗

Zion-Instrumentation

C++ · gRPC · Yocto

  • On-device management and observability daemons
  • networkd for interfaces, wireless, routing, firewall and WireGuard; monitord for resources and storage wear
  • faults and alarms with standard alarm fields, declared by applications
  • telemetry with a health score, plus log collection and live tail
  • OTA apply, confirm and rollback, and encrypted backup and restore
View repository ↗

Zion-HQ

Python · gRPC · web

  • Fleet-management API for devices, telemetry, alarms and faults
  • Multi-tenant model with users and role-based access control
  • Agent gRPC gateway with device pairing and stale-connection sweeping
  • Web frontend for operators
  • Database migrations and Docker Compose infrastructure
View repository ↗

Zion-Hardware

Board design

  • Hardware documentation home for AMD Xilinx Zynq
  • Read-only reference, committed by the hardware engineer
  • Documentation folder in place, populated as the board design is published
  • Planned: schematics, bill of materials and datasheets
  • Will be the source of truth for OS and HAL work
View repository ↗

Validation & Verification

Zion-HAL

C++17 · protobuf

  • Hardware abstraction layer shared by the client and the target boards
  • Protobuf contracts for common, client and HAL services
  • Module interfaces from CPU and memory to GPIO, storage, networking and cameras
  • Platform bindings per board, with an STM32 transport
  • Per-module test programs, CMake build and Doxygen API docs
View repository ↗

Zion-Client

C++17 · gRPC

  • On-device daemon that makes the board remotely controllable
  • gRPC service that exposes the HAL modules
  • Run orchestration that sequences tests and their lifecycle
  • Durable local spool so results survive disconnects
  • Adapter registry, runtime configuration and systemd deployment
View repository ↗

Zion-Server

C++ · Drogon · PostgreSQL

  • Central backend for validation runs
  • REST API for auth, targets, modules, templates, runs, schedules, logs, alerts and OTA
  • gRPC streams to clients with heartbeats and backpressure
  • PostgreSQL storage with versioned migrations
  • Docker, CMake presets and CI workflows
View repository ↗

Zion-Dashboard

Next.js · TypeScript

  • Operator console for validation runs
  • Routes for dashboard, runs, live run detail, logs, modules and reporting
  • Live run view over a server-sent event stream
  • Module catalog, settings, retention and OTA controls
  • REST and streaming contract tests with pytest, plus Vitest unit tests
View repository ↗

Zion-PySDK

Python

  • Typed Python client for the HAL service
  • Generated protobuf and gRPC bindings with type stubs
  • Connection setup and service discovery
  • One-shot calls, long-running runs, monitoring and events
  • Examples and tests against a fake server
View repository ↗
